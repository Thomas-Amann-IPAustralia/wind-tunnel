## 6.7

No. Currently, no clear processes for human intervention or safely disengaging the AI system have been established, as the project is in an early concept stage with key details marked as placeholders in the outline. To address this gap as the system is developed, the project team must establish robust human-in-the-loop (HITL) controls and disengagement protocols. Specifically, in accordance with ISM Control ISM-2113, the AI application must be configured to flag organisationally defined risky actions for human approval prior to execution (ISM, p.120). For agent-based systems, manual approval should be implemented for sensitive operations before autonomous agents can continue execution (LLMSVS, §Control objective). Furthermore, clear protocols must be created for immediate intervention, including the capability to quickly take the system offline or disengage it if it displays undesirable behavior (LLMSVS, §Control objective). To ensure reliability, the deployment environment should support automated rollbacks to quickly revert the AI system to its last known good state if a compromise or unresolvable issue is identified (Deploying AI Securely, p.6). Finally, incorporating human oversight helps detect and correct anomalies while maintaining operator training, which is critical in emergencies (AI in OT Principles, p.19).

## 7.3

No. There are currently no measures in place to address security risks arising from the operation of the AI, given the placeholders in the project outline. Because this use case involves an agentic AI system utilizing autonomous agents to process large datasets, several critical security measures must be established during design and deployment. First, to mitigate risks associated with excessive agency and unauthorized actions, the system must enforce strict privilege controls and least privilege access, restricting the model's access privileges to the minimum necessary (OWASP LLM Top 10, p.9). Agent-based tools should only expose access to the specific tools and plugins required for the current task (LLMSVS, §Control objective), and API tokens for third-party services must be scoped to the minimum required (LLMSVS, §Control objective). Second, the host executing agent tools and plugins must be appropriately segregated from other internal components and restricted from making arbitrary egress network requests to prevent data exfiltration (LLMSVS, §Control objective). Executing agents in a sandboxed ephemeral environment is also recommended to reduce the risk of code execution vulnerabilities (LLMSVS, §Control objective). Third, the project must implement continuous monitoring and logging of model behavior, treating logs as sensitive assets and protecting their confidentiality, integrity, and availability (Secure AI Dev Guidelines, p.12; Deploying AI Securely, p.6). Finally, the organization's cybersecurity incident response plans must be updated to incorporate AI-specific failure states, malicious activity, and incident management procedures (AI in OT Principles, p.20; Secure AI Dev Guidelines, p.14).
